<task type="tracer">
  <name>Task 1: Backend Checkout, Khalti Sandbox Initiate &amp; Verification APIs</name>
  <files>backend/stores/api.py, frontend/src/lib/api.ts</files>
  <action>
    Implement store checkout and payment endpoints in `backend/stores/api.py`:
    1. `StoreCheckoutQuoteView` (`POST /api/stores/<storeSlug>/checkout/quote/`):
       - Takes items array: `[{ variant_id, quantity }]` and `district`.
       - Computes server-authoritative `subtotal_minor`, `shipping_minor` (Inside Valley for Kathmandu/Lalitpur/Bhaktapur, Outside Valley for others; free if above threshold), and `total_minor`.
    2. `StoreCheckoutPlaceView` (`POST /api/stores/<storeSlug>/checkout/place/`):
       - Login-gated (ensures shopper customer account exists).
       - Takes items, delivery address payload, and `payment_method` (`KHALTI` | `COD`).
       - If `COD`: creates Order with status `CONFIRMED`, `payment_status="COD_PENDING"`, creates OrderItems & initial `OrderEvent`, returns order object.
       - If `KHALTI`: creates Order with status `PENDING_PAYMENT`, `payment_status="UNPAID"`, initiates Khalti epayment via `https://dev.khalti.com/api/v2/epayment/initiate/` (using store's encrypted key or fallback platform sandbox key), stores `pidx` in `payment_ref`, returns Khalti payment URL (`payment_url`).
    3. `StoreKhaltiVerifyView` (`POST /api/stores/<storeSlug>/checkout/khalti-verify/`):
       - Takes `pidx` and `order_id`.
       - Queries Khalti `epayment/lookup/` to verify transaction state is `Completed`.
       - Updates Order status to `PAID`, `payment_status="PAID"`, appends `OrderEvent`, sends confirmation email.
    4. Add typed API clients in `frontend/src/lib/api.ts`.
  </action>
